## 2. ❓ "왜 그렇게 split 했나?"

### Train:Valid:Test (~7:2:1)
> "대부분 공개 데이터셋(Roboflow·Kaggle)이 이미 train/valid/test로 나뉜 걸 그대로 병합해 ~7:2:1이 됐습니다.
> **valid는 학습 중 튜닝·조기종료(patience)용, test는 학습에 한 번도 안 쓴 최종 평가용**으로 분리했고,
> 이 test 분리 덕분에 **round6 vs round7을 객관 비교**해서 최종 모델을 정했습니다."

### 클래스 Split = 의도적 (목표 1:2:3)
> "클래스는 일부러 조정했습니다. ok(착용)가 압도적으로 흔해서 그대로 두면 모델이 ok만 잘 맞춥니다.
> 그래서 R5/6에서 **ok만 언더샘플(목표 1:2:3)** 해 fallen·no_helmet 학습을 강화했고,
> **fallen·no_helmet은 안전 핵심이라 절대 줄이지 않았습니다.**"

**1:2:3을 그 비율로 한 이유 (클래스 특성)**
| 클래스 | 비중 | 이유 |
|---|---|---|
| **ok** | 3 (최대) | 안전모 착용 판정이 핵심 → 충분히 학습. 원래 가장 흔함(전체 8.4배)인데 **3배로 낮춰 과편중만 방지** |
| **no_helmet** | 2 | **캡·모자·맨얼굴이 다 섞인** 가장 다양한 클래스 → 어느 정도 양 필요 |
| **fallen** | 1 (최소) | 데이터 적지만 **누운 자세 패턴이 단순**해 의외로 잘 인식 → 적게 줘도 충분 |

> 한 줄: **"흔하고 핵심인 ok는 충분히, 다양한 no_helmet은 적당히, 단순·소수인 fallen은 최소 — 데이터 특성에 맞춘 1:2:3"**

## 3. ❓ "증강(augmentation)은 어떤 클래스에 적용?"

### ⚠️ 핵심: **클래스별이 아니라 "전체 이미지"에 적용**
YOLO 표준 증강(degrees·mixup·copy_paste 등)은 **학습 이미지 전체(모든 클래스)에 똑같이** 적용됨. **클래스를 타겟할 수 없음.**

→ **클래스별 조절은 증강이 아니라 데이터 샘플링(1:2:3)으로** 함. (※ 흔히 헷갈리는 부분: 클래스 제어=데이터 비율 / 증강=전체 적용)

### 단, 일부 증강은 특정 클래스를 "염두에 두고" 선택
| 증강(R6~ 레시피) | 의도한 클래스 | 효과 |
|---|---|---|
| **copy_paste 0.1** | fallen·no_helmet(소수) | 객체 오려붙여 **드문 클래스 인스턴스 증가** → 불균형 보조 완화 |
| **mixup 0.15** | ok ↔ no_helmet 경계 | 캡모자 vs 안전모 경계 **강인하게** |
| **degrees 15** (R9/10은 30 + flipud 0.3) | fallen | 쓰러진/기운 **다양한 방향** 학습 |
| **hsv (색·밝기)** | ok·전체 | 안전모 색 다양화 + 현장 조명 변화 |

> 답변: **"증강은 이미지 전체에 적용됩니다(클래스 타겟 불가). 클래스별 조절은 데이터 비율(1:2:3 샘플링)로 했고, 증강은 소수 클래스(copy_paste)·경계(mixup)에 도움 되는 걸 골라 적용했습니다."**
> (꼬리질문 "증강으로 fallen만 늘릴 수 있나?" → "표준 YOLO론 불가, copy_paste가 간접적으로 소수 클래스를 늘려주는 정도")

## 4. ❓ "YOLO11도 있는데 왜 YOLOv8s냐?"

### 가장 강한 답 — "모델이 병목이 아니었다 + 실제로 더 큰 모델을 시도해봤다"
> "저희 병목은 모델이 아니라 **데이터·라벨·클래스 불균형·도메인 갭**이었습니다.
> 실제로 **더 큰 yolov8m을 시도(runs3)했는데 속도만 느려지고 정확도 이득은 미미**해서 경량 v8s로 회귀했습니다.
> 더 크거나 새로운 모델로 바꿔도 그 병목은 안 풀립니다."

### 보조 근거 4가지
| 이유 | 설명 |
|---|---|
| **실시간 경량 우선** | CCTV 실시간이 목표 → small 속도 중요. v8s로 이미 **mAP 0.95+** 달성 |
| **검증된 안정성** | v8s는 출시 오래돼 문서·버그수정·프로덕션 사례 풍부 (v11은 더 새로워 검증 사례 적음) |
| **실험 재현성** | 10라운드를 **모델 고정**으로 진행 → 데이터·증강만 변수로 비교. 중간에 모델 바꾸면 라운드 비교 무의미 |
| **교체 용이성** | YOLO11도 **같은 ultralytics API** → 추후 `YOLO('yolo11s.pt')` 한 줄로 교체·재학습 가능 |

### 정직한 마무리
> "YOLO11이 같은 데이터에서 1~2%p 올려줄 가능성은 있습니다. 하지만 이번 교훈은 **'모델보다 데이터가 병목'**이었고,
> 그래서 검증된 v8s에 집중했습니다. **다음 단계로 YOLO11s 재학습은 쉽게 시도 가능**합니다."

→ 인상: **유행 따라 최신 모델 쓰는 게 아니라, 병목을 정확히 알고 의사결정**. (v8m 시도 실패가 데이터로 증명된 결정적 근거)
